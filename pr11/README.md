***Файл із кодом знаходиться в даній директорії під назвою task_by_var_6.c***

За замовчуванням у сучасній Ubuntu увімкнено захисний механізм Yama LSM, 
який забороняє будь-яким процесам підключатися до інших за допомогою ptrace.
Щоб наш код міг працювати, цю функцію потрібно тимчасово вимкнути.

Зробимо це за допомогою команди:
```bash
sudo sysctl -w kernel.yama.ptrace_scope=0
```

Далі нам необхідно скомпілювати дану програму, зробимо це за допомогою команди:
```bash
gcc -Wall task_by_var_6.c -o task
```

Для демонстрації заміни стандартного механізму нам потрібен будь-який довготривалий процес. 
Найпростіший спосіб - запустити системну утиліту sleep у фоновому режимі:
```bash
sleep 500 &
```

Одразу після чого отримуємо ось такий вивід:
```bash
sleep 500 &
[1] 3774
```

Запустимо нашу програму та побачимо як "завмре" наш термінал:

Вивід:
```bash
sudo ./task 3774
[sudo] password for drogobytskyyy:
[Monitor] Attaching to process 3774...
[Monitor] Successfully attached. Monitoring for crashes...
```

Так як процес sleep сам по собі не впаде, пілключимось із другого терміналу та штучного вбʼємо його командою:
```bash
kill -s SIGSEGV 3774
```

І нарешті після цього ми побачимо у першому терміналі очікуваний інформативний вивід про перехоплення.

***Висновок***

  У ході виконання практичної роботи було розроблено та протестовано програму на мові C,
яка успішно замінює стандартний механізм логування ядра Linux (Core Dump) при аварійному завершенні процесів. 
Реалізована архітектура базується на низькорівневому системному виклику ptrace та конфігурації модуля безпеки Yama LSM(ptrace_scope = 0). 
Це дозволило створити автономний процес-монітор, 
який здатний легітимно підключатися до сторонніх запущених у системі додатків за їхнім PID, 
повністю перехоплювати критичні сигнали падіння та блокувати примусове знищення цілі операційною системою.

  Успішність розробленого рішення було наочно продемонстровано на прикладі фонового процесу sleep 500 (PID: 3774), 
роботу якого було перервано штучним надсиланням сигналу порушення сегментації пам'яті SIGSEGV (11). 
Замість стандартного «сліпого» завершення програми, створений логгер миттєво перехопив контроль над контуром виконання процесора, 
зафіксував факт аварії та здійснив повну ліквідацію цілі лише після збору всієї необхідної діагностичної інформації.

  Отриманий консольний вивід демонструє глибокий аналіз стану процесу в момент аварії, 
фіксуючи точний зріз архітектурних регістрів віртуальної машини ARM64. 
Зокрема, значення регістру PC (Program Counter) вказує на точну адресу інструкції збою, 
а виклик PTRACE_PEEKTEXT дозволив зчитати сирий машинний код цієї інструкції (0xaa0003f3d4000001). 
Крім того, завдяки зчитуванню системного файлу /proc/3774/maps логгер вивів розширену карту віртуальної пам'яті, 
зіставлення якої з регістром PC доводить, що падіння сталося всередині базової системної бібліотеки /usr/lib/aarch64-linux-gnu/libc.so.6.

  Розроблений алгоритм має високу практичну цінність для відмовостійких систем (Fault-tolerant systems), 
високонавантажених серверів та вбудованих пристроїв. 
Він доводить можливість побудови ефективних кастомних систем моніторингу, які автоматично генерують деталізовані звіти про помилки у реальному часі. 
Такий підхід забезпечує розробників вичерпним контекстом для дебаггінгу, 
не перевантажуючи дискову підсистему накопиченням важких бінарних файлів дампів пам'яті.
